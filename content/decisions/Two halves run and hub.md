# Two halves run and hub

> The game is two distinct halves: the run (active skill-based expedition) and the hub (scaling production engine).

## Reasoning

A single unified loop couldn't satisfy the two different emotional registers: the skill/tension of a trade expedition and the calm satisfaction of watching a production engine scale. Splitting into two halves lets each be designed on its own terms. The run is the main event; the hub provides memory and consequence across runs.

The design rule everything bows to: **build and validate the run as a standalone toy first.** The hub slots on top of a proven core.

## Rejected

- **Single unified loop** — conflates the active skill game with the idle engine; neither gets to be what it needs to be.
- **Hub-first design** — designing the hub before the run is proven risks building a reward wrapper around a core that isn't fun.
