# Actions per town and towns per run

> ✅ **ANSWERED 2026-07-01** — Moot — the run is gates with a round budget, not towns with per-town actions. See [[decisions/Escalating score gates structure the run]].

> How many actions does each town give? How many towns make a run?

## Options on the table

**Actions per town:**
- The design doc starts with ~3 as the hypothesis.
- ~3 creates a natural 3-beat rhythm: assess & execute → biggest play → pivot for next town.
- Fewer actions → more scarcity, harder choices, shorter towns.
- More actions → more room to both invest and execute; towns feel longer.

**Towns per run:**
- The prototype spec suggests ~10–12 towns per run as a starting point.
- Fewer towns → shorter runs, less accumulation, less engine build-up.
- More towns → longer runs, more powerful engines, but longer commitment per run.

## Notes

These are the **key tuning knobs** of the whole game. They cannot be resolved theoretically — tune in prototype. They are also tightly coupled to each other: a run with 3 actions × 10 towns = 30 total action decisions; that's the run's total skill budget. The feel target is a ~15-minute satisfying run.

These numbers also interact with the verb list (see [[open/What an action can do]]) and the route tradeoff (see [[open/Route tradeoff axis]]).
